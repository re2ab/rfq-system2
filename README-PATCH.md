# پچ M11 + M12 — ویرایش آنلاین (ONLYOFFICE) + منوی سند جدید

این پچ فقط شامل فایل‌هایی است که از آخرین پچ تحویلی به بعد تغییر کرده‌اند یا تازه اضافه شده‌اند. ساختار پوشه‌ها همان ساختار پروژه‌ی خودتان است — کل محتوای این پوشه را انتخاب و روی پوشه‌ی اصلی سیستم (ریشه‌ی پروژه روی Railway/کامپیوترتان) Paste کنید تا جای فایل‌های قدیمی بنشیند.

## چه چیزی اضافه/تغییر کرده؟

**۱. ویرایش آنلاین سند (M11)** — دکمه‌ی «ویرایش آنلاین» در صفحه‌ی هر سند (وقتی فایل آن Word/Excel و هنوز Draft باشد) یک ویرایشگر واقعی شبیه Word/Excel را مستقیم در مرورگر باز می‌کند — دقیقاً مثل Google Docs. این ویژگی به یک سرویس جدا به نام **ONLYOFFICE Document Server** نیاز دارد که باید خودتان روی Railway بالا بیاورید (پایین همین فایل، مرحله‌به‌مرحله توضیح داده شده). تا وقتی آن سرویس را بالا نیاورید، دکمه اصلاً نمایش داده نمی‌شود — هیچ‌چیز از کار نمی‌افتد.

**۲. منوی «سند جدید» شبیه Zoho (M12)** — در صفحه‌ی اسناد، به‌جای چند دکمه‌ی پراکنده، یک دکمه‌ی منودار «سند جدید» اضافه شده با این گزینه‌ها:
- سند Word ← ایجاد سند خالی / ایجاد از تمپلیت آماده
- سند Excel ← ایجاد سند خالی / ایجاد از تمپلیت آماده
- آپلود فایل
- وارد کردن از فضای ابری (Google Drive)

«ایجاد سند خالی» یک ویژگی کاملاً تازه است: یک فایل Word/Excel کاملاً خالی برای پرونده‌ی انتخابی ثبت می‌شود تا بلافاصله با همان دکمه‌ی «ویرایش آنلاین» از صفر نوشته شود — دقیقاً مثل زدن «سند خالی» در Google Docs/Zoho Writer.

**۳. حذف اجباری برای مدیر سیستم** — تا امروز اگر سندی منتشر/قفل شده بود یا قالبی قبلاً برای ساخت سند استفاده شده بود، حذفش برای همه (حتی مدیر) مسدود بود. حالا **فقط نقش admin** یک دکمه‌ی جدا و با هشدار قوی‌تر می‌بیند («حذف — نادیده گرفتن قفل» / «حذف اجباری») که همین محدودیت را دور می‌زند — برای پاک‌سازی داده‌ی تستی/اشتباهی که روی سیستم واقعی ساخته‌اید. کاربران دیگر همچنان با همان محافظت قبلی مواجه می‌شوند. (دکمه‌ی حذف سند هم از این پس یک permission جدا به اسم `document.delete` می‌خواهد — پایین توضیح داده شده که باید seeder را دوباره اجرا کنید.)

**۴. اصلاحات کوچک:**
- صفحه‌ی «اسناد» تب پرونده: فهرست دیگر فقط شماره‌ی سند را نشان می‌دهد (لینک به سند) — نوع سند زیرش دیگر نوشته نمی‌شود، چون خودِ شماره برای شناسایی کافی است.
- صفحه‌های جدیدی که در این پروژه ساخته شده بودند (ساخت سند از قالب، آپلود، Import از Drive، تنظیمات قالب) قبلاً در یک ستون باریک و وسط‌چین بودند؛ حالا مثل بقیه‌ی صفحه‌های سیستم تمام‌عرض‌اند.

## فایل‌های این پچ

فایل‌های کد (php/blade) + دو فایل باینری تازه:
```
storage/app/blank-templates/blank.docx
storage/app/blank-templates/blank.xlsx
```
این دو، اسکلت کاملاً خالی Word/Excel هستند که «ایجاد سند خالی» از رویشان کپی می‌سازد — **حتماً همراه بقیه‌ی فایل‌ها Paste شوند**، وگرنه آن گزینه با خطا مواجه می‌شود.

## مراحل نصب روی Railway

### ۱. فایل‌ها را جایگزین کنید
کل این پوشه را روی ریشه‌ی پروژه Paste کنید (جای فایل‌های هم‌نام قبلی می‌نشیند) و مثل همیشه deploy کنید.

### ۲. Permission تازه را seed کنید
یک بار این را روی سرویس Railway اجرا کنید (از تب Shell/Deploy یا هر راهی که قبلاً برای seed کردن استفاده می‌کردید):
```
php artisan db:seed --class="Database\Seeders\PatchDocumentEngineSeeder"
```
این کاملاً امن و additive است (چیزی را reset نمی‌کند) — فقط permission تازه‌ی `document.delete` را می‌سازد و به نقش‌های admin/مدیر فنی/مدیر مالی می‌دهد.

### ۳. سرویس ONLYOFFICE Document Server را بالا بیاورید (اختیاری، فقط برای ویرایش آنلاین)
اگر فعلاً فقط منوی «سند جدید» و حذف اجباری را می‌خواهید، این مرحله را می‌توانید فعلاً رد کنید — بقیه‌ی سیستم بدون آن هم کامل کار می‌کند.

روی Railway:
1. یک **سرویس جدید** در همان پروژه بسازید: «New Service» → «Docker Image» → نام ایمیج: `onlyoffice/documentserver`
2. برای آن سرویس این متغیرهای محیطی را بگذارید:
   - `JWT_ENABLED` = `true`
   - `JWT_SECRET` = یک رشته‌ی تصادفی و طولانی و مخفی، خودتان بسازید (مثلاً با یک تولیدکننده‌ی رمز آنلاین یا `openssl rand -hex 32`) — این را جایی یادداشت کنید، در مرحله‌ی بعد دوباره لازمش دارید.
3. پورت داخلی این ایمیج ۸۰ است — از تنظیمات Networking همان سرویس یک دامنه‌ی عمومی (Public Domain) برایش بسازید (Railway معمولاً خودش پیشنهاد می‌دهد، شبیه `xxxx.up.railway.app`).
4. صبر کنید تا دیپلوی کامل شود و آدرس عمومی‌اش را باز کنید — یک صفحه‌ی خوش‌آمد ONLYOFFICE باید باز شود (اگر `/healthcheck` خطا داد نگران نشوید، همین صفحه‌ی خوش‌آمد کافی است).

### ۴. اتصال اپ اصلی به آن سرویس
روی همان سرویس Laravel فعلی‌تان (نه سرویس تازه)، این دو متغیر محیطی را اضافه کنید:
- `ONLYOFFICE_DS_URL` = آدرس عمومی سرویس ONLYOFFICE که در مرحله‌ی قبل ساختید (بدون `/` انتهایی) — مثلاً `https://onlyoffice-production.up.railway.app`
- `ONLYOFFICE_JWT_SECRET` = **دقیقاً همان** مقداری که در مرحله‌ی قبل برای `JWT_SECRET` گذاشتید

دوباره دیپلوی کنید (یا صبر کنید Railway خودش به‌خاطر تغییر env var ری‌استارت کند).

### ۵. تست
1. یک سند Draft (Word یا Excel) باز کنید — یا از منوی «سند جدید» یک سند خالی بسازید.
2. باید دکمه‌ی «ویرایش آنلاین» را ببینید (کنار دانلود/PDF). رویش بزنید.
3. باید ویرایشگر شبیه Word/Excel در یک تب جدید باز شود. کمی بنویسید، تب را ببندید (یا صبر کنید autosave بزند).
4. برگردید به صفحه‌ی سند و دوباره دانلودش کنید — باید همان تغییراتی که در ویرایشگر آنلاین نوشتید در فایل دانلودشده باشد. این یعنی مسیر ذخیره (callback) درست کار می‌کند.

اگر مرحله‌ی ۴ کار نکرد (تغییرات ذخیره نشد)، معمول‌ترین علت این است که `ONLYOFFICE_DS_URL` روی اپ اصلی از بیرون (نه فقط از داخل شبکه‌ی Railway) قابل‌دسترس نیست — سرویس Document Server باید بتواند به آدرس عمومی خودِ اپ Laravel هم POST بزند، پس هر دو سرویس باید دامنه‌ی عمومی (نه فقط داخلی) داشته باشند.
